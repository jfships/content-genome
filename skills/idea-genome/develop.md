# Step 3. Develop (every path, own idea included)

Purpose: turn a captured idea into a worked-through one, with the creator. Claude brings research and options; the creator decides. Answers are recorded in the creator's words under `## Develop rounds` in the record.

Develop settles the idea's shape (stance, rough structure, cast, tone, payoff, twist). It does not write the script or plan beats; that is video-genome's plan.

**A Short / Reel** runs 3a, 3c, 3e and 3f here, but `short-form.md` instead of 3b and Hooks.

## 3a. Research the raw material (live, with sources)

Before the first question, search for:
- **Examples of the thing itself**: if the idea parodies, reviews, tests or reacts to something, collect 8–15 real instances of it (phrases, tropes, formats, headlines). These become option lists in the rounds.
- **Gap scan**: who already made this video, which angle each took, which nobody took.
- **Demand**: what people search or ask about the topic.

Share findings as short option lists inside the questions, not as a report. Keep links for `## Sources`.

## 3b. Question rounds (1–3 rounds, up to 4 questions each)

Pick the questions the idea actually leaves open, from:
- **Stance**: what is the creator's take? (for, against, roast + fair concession, curious test)
- **Structure**: the rough shape at idea level (one test, montage + set pieces, countdown, before/after). Also ask which sections are written to be clippable: self-contained, each opening with a standalone hook line and closing with a one-line summary. Those become "Shorts this video can feed".
- **Cast**: who appears and who plays what. Apply the likeness check (SKILL.md) before offering any generated version of the creator.
- **Tone**: how it should feel, with one plain example per option.
- **Payoff / proof**: what the viewer walks away with and what real proof backs it.
- **The twist / turn**: what changes the video's direction and roughly when. Long videos only; required there.

Rules: every option gets a plain one-line setup; Recommended option first; offer research findings as options (multi-select when the creator might want several). After each round, play back in 2–3 lines what is now settled and what is still open. Stop when nothing important is open, max 3 rounds.

## 3c. Voting page (optional, per round)

When a choice is visual (a look, a set piece, a thumbnail direction, a costume, a scene), offer a voting page instead of words: one published Artifact page with 2–6 labeled options (reference images found online with credit, or quick generated sketches labeled "sketch, not final"), one line each, and a way to pick. Its footer carries the credit line (SKILL.md "Credit line"). Use it only when the creator would judge it by looking. If Artifacts aren't available, show the images inline and ask.

## 3d. Split check

Ask: is this one idea or two? Signs: two different promises, two audiences, or a section that could stand alone as its own video. If so, recommend the split: the extra part becomes a new bank row (`source: split from IDEA NNN`, status `raw` or `parked`) and gets its own ID. Creator decides.

**Shorts:** two Shorts that overlap (one sits inside the other, or both make the same point) are one Short, unless each passes the stranger test with a different message (`short-form.md` S12).

## 3e. Versions to test

Ask in the develop rounds: is there anything the creator wants to try in more than one version before deciding? Offer what's actually open: the hook, the cast (who plays what), a moment or set piece, a title, a look. Also flag any element nobody has tried yet (a performance, a generated character, an effect, a new format) as a candidate.

For each item the creator wants to test, list the versions and the cheapest test type that would let them judge:
- **Free:** rough draft, existing assets, phone recording, text and placeholders.
- **Cheap:** low-res or few-credit generations.
- **Paid:** anything more; quote the cost first, and the creator approves before it runs.
Generated versions of the creator only after the likeness check (SKILL.md) passes.

Then ask once (AskUserQuestion, plain setup per option):
- **Test them in video-genome (Recommended):** video-genome runs the table before the full build, cheapest first, and the creator picks after seeing them.
- **Decide now:** settle each item here with one more question round; the table records "decided: <pick>".
- **Skip:** build with the current pick.

Write it as `## Versions to test` in the record. That table is what video-genome reads; nothing else is needed for it to act. If a test is free and takes minutes, offer to run it right here instead.

## 3f. Only-you line

Write one line: why only this creator could make this video (their proof, their position, their story). If no line holds up, say so; it lowers Personality fit and usually means the angle needs work.

## Hooks (Step 6, after titles; long videos)

A Short's hook is `short-form.md` S5 (1–2 s, three layers, word for word). This section is long-form.

Write 2–3 hook concepts for the first 10 seconds. Each: one line of what's seen and said, plus why it works and what it costs to draft. Rank them with a reason. The creator doesn't have to decide here: ranking is enough, and video-genome drafts the top ones cheaply so the creator can judge by watching. Every hook pays off the title within 10 seconds.
